# Ajude a deixar a tradução melhor 🌱

[English](CONTRIBUTING.en.md)

Obrigado por participar! Você pode contribuir com um relato, uma sugestão de redação, revisão de termos ou melhorias nos guias. Não precisa entender programação nem encontrar o arquivo interno do jogo.

## Relatar um problema

Abra [uma issue pelo formulário](https://github.com/jhonsantosx/ACNL-Welcome-Amiibo-PTBR/issues/new/choose). Antes, procure se alguém já relatou a mesma fala.

Inclua:

- **Versão do patch**, como aparece no `VERSAO.txt` do download.
- **Plataforma**: 3DS/Luma ou Citra; informe a versão se souber.
- **Onde aconteceu**: morador, loja, evento, menu ou etapa do jogo.
- **O que apareceu** e o que parece errado.
- **Print ou foto** com a caixa inteira visível. Se a frase continua, inclua a próxima tela.
- **Como repetir**, se souber. Não precisa reproduzir tudo de novo para enviar o primeiro relato.

Exemplos úteis: “a palavra prefeitura quebrou no meio”, “o nome do item termina antes de completar”, “a opção do menu não corresponde à resposta”, “a fala muda para inglês quando menciona uma moradora”.

Fotos de celular servem. Não envie CIA, ROM, chaves, dados de conta ou saves pessoais. Recorte notificações ou informações privadas do computador que apareçam ao redor do jogo.

## Sugerir uma redação

Use o formulário **Sugestão de tradução** e envie o texto atual, sua proposta e uma explicação breve. Se conseguir, acrescente um print para vermos o espaço disponível e o contexto.

Preferências atuais do projeto:

- Português brasileiro, com **você** e linguagem natural; **tá/pra** cabem nas falas informais.
- Preservar o humor e a personalidade de cada personagem.
- Evitar gênero fixo para o jogador quando a frase não o exige.
- Manter **Bells**, **Hino da cidade** e **Decretos** como decisões atuais.
- Não cortar palavras automaticamente para caber. Preferir uma formulação mais curta que preserve o sentido.

Essas escolhas podem ser discutidas. Uma sugestão não precisa seguir o texto atual se trouxer uma melhora clara.

## Contribuir com arquivos

Para documentação, abra um pull request com uma mudança por assunto. Para textos do jogo, comece por uma issue: este repositório público contém os guias e os pacotes de download, enquanto a montagem e a revisão do catálogo ainda são mantidas no projeto de trabalho.

Evite anexar arquivos binários editados sem combinar a base primeiro. Os comandos internos controlam nomes, gênero, escolhas, cores, pausas e tamanho. Remover um comando ou alterar a posição de uma resposta pode quebrar a conversa mesmo quando o texto parece correto.

Ao integrar uma sugestão, o mantenedor deve registrar o crédito e a issue nas notas da versão. Não há promessa de prazo para análise. Relatos e comentários devem tratar as pessoas com respeito; discordâncias sobre estilo fazem parte da revisão.
